# 花生账本 · 关键决策记录（ADR）

> 状态以 0.1.13 为基线。仅记录会影响后续迭代的决策。

## ADR-001 纯本地、无服务端

**日期**：2026-10  
**状态**：已采用  
**决策**：不实现登录、云同步、网络接口；账本和备份全部本地。  
**原因**：离线场景、隐私、实现成本。  
**影响**：数据丢失/换机需要手动备份；未来云同步需新增独立同步层，不能污染本地模型。

## ADR-002 数据 schema v1，不做旧版本兼容

**日期**：2026-10-23（0.1.11/0.1.13 基线）  
**状态**：已采用  
**决策**：本地 JSON 和备份统一 schema v1；不保留 schema v2/旧字段回退/旧数据迁移。  
**原因**：APP 尚未发布，避免在早期背负兼容复杂度。  
**影响**：破坏性字段变更必须同步提升 schema，并在发布后重新制定迁移策略；开发数据不保证跨 schema 可读。

## ADR-003 单 Activity + LedgerState 状态容器

**日期**：2026-10  
**状态**：已采用，存在技术债  
**决策**：不引入 MVVM/DI 框架，`LedgerState` 集中持有数据和业务操作，Compose 直接订阅。  
**原因**：单 module、本地应用、状态共享密集，减少样板。  
**影响**：`LedgerState` 偏大（约 1.1k 行）；规模扩大时应拆分为 Ledger/Settings/Backup/Calendar 控制器。

## ADR-004 采购/销售/供货商/收购商命名

**日期**：2026-10-23  
**状态**：已采用  
**决策**：领域字段统一为 `PURCHASE/SALE`、`purchases/sales`、`supplierName/buyerName`、`purchaseTypes/saleTypes`。  
**原因**：与前端中文文案和业务语义一致，避免 farmer/name 等泛化命名。  
**影响**：schema v1 使用新字段；旧字段不再兼容。

## ADR-005 销售必须绑定设置中的收购商

**日期**：2026-10  
**状态**：已采用  
**决策**：新增销售只能从设置 `buyers` 选择；销售页无现场新增/改名；设置改名同步历史记录。  
**原因**：避免同一收购商出现多个自由文本变体，保证统计口径。  
**影响**：删除/失效设置项需考虑历史记录；新增销售在无收购商时受阻。

## ADR-006 采购供货商自动命名

**日期**：2026-10-23  
**状态**：已采用  
**决策**：默认名称 `供货商N`，按当天序号生成；输入框可改；姓氏框提取序号显示。  
**原因**：快速录入，同时保留真实名称能力。  
**影响**：旧“户N”/纯数字自动名称在未发布阶段不再做迁移。

## ADR-007 备份策略

**日期**：2026-10-06  
**状态**：已采用  
**决策**：本地版本化 JSON 备份；默认每天一次、保留30天；后台触发；恢复前安全备份；高版本备份阻断。  
**原因**：无后台服务，后台时数据已落盘，适合快照。  
**影响**：应用被系统直接杀死时可能错过当天自动备份；备份位于应用目录，卸载/清数据会删除。

## ADR-008 称重字段顺序与键盘流

**日期**：2026-10-23  
**状态**：已采用  
**决策**：单价左、重量右；单价空聚焦单价，有值聚焦重量；IME：单价 Next → 重量，重量 Done → 保存；金额不自动聚焦。  
**原因**：符合录入顺序，减少一次点击；避免跳到金额字段。  
**影响**：金额手动编辑仍需点击；重量为0时 Done 仍走既有“关闭不保存”逻辑。

## ADR-009 新安装空白账本

**日期**：2026-10  
**状态**：已采用  
**决策**：不预置演示采购/销售记录；只保留默认类型/收购商设置。  
**原因**：真实用户第一次使用不被示例数据干扰。  
**影响**：首次启动为空态；截图/演示需手动录入数据。
